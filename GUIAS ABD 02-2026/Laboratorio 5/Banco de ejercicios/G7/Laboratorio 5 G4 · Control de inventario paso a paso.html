Paso 0.3 · Preparación
Ubicar la carpeta de respaldos
El archivo .bak lo escribe el servicio de SQL Server, no su usuario de Windows o de su Mac.
Por eso la ruta debe existir en el servidor y esa cuenta de servicio debe poder escribir ahí.
Convención de hoy: en cada comando, cambien <ruta> por su carpeta, terminada en \ (Windows) o / (Linux).
-- SQL Server 2019 o posterior SELECT SERVERPROPERTY('InstanceDefaultBackupPath')        AS carpeta_respaldos;
Windows (ruta típica)
C:\Program Files\Microsoft SQL Server\ MSSQL16.MSSQLSERVER\MSSQL\Backup\
Docker o Linux
/var/opt/mssql/data/ o /backup/ si existe

Paso 0.4 · Preparación
Guardar un respaldo del estado inicial
WITH INIT
Sobrescribe lo que tenga ese archivo. Sin INIT, cada respaldo se agrega al final y el archivo acumula varias copias.
CHECKSUM
Comprueba las páginas mientras respalda y detecta daños.
NAME
Una etiqueta que luego aparece en el historial.
RESTORE VERIFYONLY
Confirma que el archivo está completo y se puede leer, sin restaurar nada.
USE master; BACKUP DATABASE Lab05_G04 TO DISK = N'<ruta>G04_base_inicial.bak' WITH INIT, CHECKSUM,      NAME = N'Lab05_G04 estado inicial'; -- ¿El archivo quedó bien? RESTORE VERIFYONLY FROM DISK = N'<ruta>G04_base_inicial.bak'; -- Mensaje esperado: "The backup set -- on file 1 is valid."
Laboratorio 5 · Grupo 4 · Paso 0 · Preparación
Para usar cuando haga falta
Volver al estado inicial
SINGLE_USER WITH ROLLBACK IMMEDIATE
Saca a todas las sesiones conectadas a la base y deshace lo que tuvieran abierto.
REPLACE
Permite sobrescribir una base que ya existe.
RECOVERY
Termina la restauración y deja la base lista para consultar.
Solo con su base de práctica. Si la base ya no existe, omitan el primer ALTER.
USE master; -- 1. Cerrar conexiones a la base ALTER DATABASE Lab05_G04   SET SINGLE_USER WITH ROLLBACK IMMEDIATE; -- 2. Restaurar el estado inicial RESTORE DATABASE Lab05_G04 FROM DISK = N'<ruta>G04_base_inicial.bak' WITH REPLACE, RECOVERY; -- 3. Reabrir la base a todos ALTER DATABASE Lab05_G04 SET MULTI_USER;

Ejercicio 3 · Paso 2b
Agregar el paso T-SQL que hace el respaldo
Comillas dobles ''
@command es texto. Una comilla simple dentro del texto se escribe dos veces.
¿Por qué @cmd?
EXEC no acepta expresiones con + en sus parámetros; la variable sí. DECLARE y EXEC van en el mismo lote, sin GO entre ellos.
@subsystem = TSQL
El paso ejecuta T-SQL, conectado a master.
Truco: prueben primero el BACKUP a mano. Si falla a mano, fallará en el Job.
DECLARE @cmd NVARCHAR(MAX) =     N'BACKUP DATABASE [Lab05_G04] '   + N'TO DISK = N''<ruta>G04_E3_job.bak'' '   + N'WITH INIT, CHECKSUM;'; EXEC msdb.dbo.sp_add_jobstep     @job_name = N'G04_Respaldo_Diario',     @step_name = N'Respaldo completo',     @subsystem = N'TSQL',     @database_name = N'master',     @command = @cmd,     @on_success_action = 1, -- éxito     @on_fail_action = 2; -- fallo

Ejercicio 3 · Paso 3
Programar a las 22:00 y asignar el servidor
220000 = 22:00:00
La hora va en formato HHMMSS. freq_type 4 significa diario.
Hora del servidor
Si SYSDATETIMEOFFSET() muestra +00:00, las 22:00 del servidor son las 16:00 en El Salvador.
sp_add_jobserver
Asigna el Job a este servidor. Sin este paso, el Agent nunca lo ejecuta.
EXEC msdb.dbo.sp_add_schedule     @schedule_name = N'G04_Diario_2200',     @freq_type = 4, -- diario     @freq_interval = 1, -- cada 1 día     @freq_subday_type = 1, -- una vez     @active_start_time = 220000; EXEC msdb.dbo.sp_attach_schedule     @job_name = N'G04_Respaldo_Diario',     @schedule_name = N'G04_Diario_2200'; EXEC msdb.dbo.sp_add_jobserver     @job_name = N'G04_Respaldo_Diario',     @server_name = N'(LOCAL)';

Ejercicio 4 · Paso 1
Confirmar FULL y crear el respaldo completo
Modelo FULL
El log conserva cada transacción hasta que se respalda. En SIMPLE se va borrando solo.
El completo inicia la cadena
No se puede respaldar el log si antes no hubo un respaldo completo.
¿Sale SIMPLE? Ejecuten ALTER DATABASE Lab05_G04 SET RECOVERY FULL; y luego el respaldo.
USE master; -- ¿Sigue en FULL? SELECT name, recovery_model_desc FROM sys.databases WHERE name = N'Lab05_G04'; -- Punto de partida: 6 movimientos SELECT COUNT(*) AS movimientos FROM Lab05_G04.dbo.InventarioControl; BACKUP DATABASE Lab05_G04 TO DISK = N'<ruta>G04_E4_full.bak' WITH INIT, CHECKSUM;

Ejercicio 4 · Paso 4
Pérdida y restauración en dos tiempos
“Restaurando…” es normal
Tras el primer RESTORE la base no se puede consultar: espera el log.
¿Usaron RECOVERY primero?
El log ya no entra. Repitan el completo con REPLACE, NORECOVERY y luego el log.
Orden obligatorio
Primero el completo, después el log. Al revés, SQL Server lo rechaza.
USE master; ALTER DATABASE Lab05_G04   SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE Lab05_G04; -- pérdida simulada -- 1) Completo, SIN terminar RESTORE DATABASE Lab05_G04 FROM DISK = N'<ruta>G04_E4_full.bak' WITH NORECOVERY; -- 2) Log, y ahora sí terminar RESTORE LOG Lab05_G04 FROM DISK = N'<ruta>G04_E4_log.trn' WITH RECOVERY;

Antes de entregar
Seis errores que vimos en todo el laboratorio
Conectado a la base
DROP y RESTORE fallan si la ventana usa Lab05_G04. Empiecen con USE master.
Ruta del equipo, no del servidor
El .bak lo escribe el servicio de SQL Server, en su propio sistema de archivos.
Olvidar INIT
El archivo acumula copias y RESTORE usa la primera, que puede ser vieja.
RECOVERY antes de tiempo
Cierra la restauración y el log ya no se puede aplicar.
Ejecutar todo dos veces
Los sp_add_* fallan porque el operador o el Job ya existen.
Agent apagado o Express
El Job se crea en msdb pero nunca se ejecuta.
